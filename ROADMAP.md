# Zero Core 1.0 -- Transformation Roadmap

**Written:** 2026-08-17
**Status:** draft, for review before any build work begins
**Scope:** from today through the end of the transformational restructuring

---

## What 1.0 means

Three things, in his words:

1. **Bring the Omarchy ideas and tools to Zero Core** -- selectively, not wholesale
2. **The restructure** -- an improved tree and a better understanding of it
3. **The beginning of DevBox**

## Who it is for

**Him. Nobody else.** He may show it off; it is not a distribution.

⚠️ THIS RULING HAS CONSEQUENCES ALREADY BAKED INTO THIS ROADMAP:

- `a profile with one consumer is ceremony, not structure` **stands unchanged.** Profiles are
  justified by three real machines -- framework16, the VM, the rescue image -- not by users.
- Decidedness survives with a different reason: **future-you should not re-litigate a decision at
  2am**, not "a stranger should not have to choose."
- **The customization-surface rule matters more, not less.** He is the user whose config gets
  overwritten. That is why he left Omarchy.
- **User-facing documentation loses its audience.** `docs/public/` is generated by `faelight-docs`
  for readers who do not exist.

### P3 -- The module shape

**Work:** one component wired end to end -- package, config, and service in a single module -- then
repeat for the rest. This is where `profiles/` and decidedness land.

**The rule being proven:** a package name may not appear anywhere except the module that also
configures and starts it. That makes "installed but not wired" impossible to express, which is the
defect measured across five components on 2026-08-16.

**Exit:** a component confirmed running by `ps`, not by a green build.

## Cosmetics -- configuration, not architecture

⚠️ AN EARLIER CLAIM IN THIS ROADMAP WAS WRONG AND IS CORRECTED HERE. Mango was flagged as
structurally limited compared to Hyprland. **It is not.** Measured 2026-08-17 from
`nix/home/dotfiles/mango/.config/mango/config.conf`:

```
blur=0                  shadows=0               border_radius=8
no_radius_when_single=0 focused_opacity=1.0     unfocused_opacity=0.95
animations=1            layer_animations=1      smartgaps=1
animation_curve_open=0.46,1.0,0.29,1
animation_curve_close=0.08,0.92,0,1
```

**Rounding already exists and is already on at 8** -- the same value Omarchy's own manual suggests.
Animations are on, with bezier curves. **Blur and shadows exist as options and are simply set to 0.**

★ **The compositor is not the limit. The cosmetics gap is configuration.**

### The real finding: the palette is already split

Mango is themed to **GitHub dark**, not Hakker Green:

| Setting | Current | Source |
| --- | --- | --- |
| `rootcolor` | `0x0d1117` | GitHub dark background |
| `focuscolor` | `0x3fb950` | GitHub success green |
| `bordercolor` | `0x3d444d` | GitHub border |
| `urgentcolor` | `0xf85149` | GitHub danger red |

Target palette: background `#000000`, primary `#00ff99`, accent `#00cc77`, highlight `#ccffee`.

⚠️ The palette split noticed on the logo **already exists in the compositor.** Closing it is four
colour values.

### The work

1. Repoint the four mango colours at the Hakker Green palette
2. Turn `blur` and `shadows` on and look at the result
3. Make the palette single-sourced rather than typed into each config -- that is INT-091's Stylix
   hybrid, consuming `config.lib.stylix.colors`

⚠️ **Blur and shadows may be off for a reason.** INT-052 records that remote-viewer renders as a
doubled surface under mango with `unfocused_opacity` plus slide animations. Turn them on, look, and
roll back the generation if they misbehave. That is what generations are for.

**Still open:** "Liquid Crazy Corners / toybox" could not be identified from a search. A link is
needed before it can be evaluated.

📍 For reference, an Omarchy theme styles: desktop, terminal, neovim, btop, mako, waybar, walker,
hyprlock. **Only terminal, neovim and the lock screen map to what Zero Core runs.** The palette is
portable; the theme files are not.
