## Context

Decisions 142 through 147 each settled one question. Read together they turned out to be saying
eight things repeatedly, in different domains.

This records those eight as laws, and — more importantly — **what each one was paid for.**

⚠️ A law with no incident behind it is a preference wearing a uniform. Every one below is traceable
to something measured in this repository during the week of 2026-08-16.

## The laws

### 1. Facts before configuration

> Record what is true; derive what should happen.

**Earned from:** the intent dependency graph. `core intent blocked` reported *"no blocked intents --
all dependencies satisfied"* across 239 of 241 intents, and that answer was **false rather than
empty**. A command that reports confidently on an empty graph is worse than one that reports
nothing, because it is trusted.

### 2. One decision, one owner

> A concern shouldn't have several competing authorities.

**Earned from:** `complete_ids` built independently in five functions, each deciding what satisfies
a dependency. `capabilities` existing at both `engine/src/capabilities/` and
`engine/src/domains/capabilities/`. Alias expansion having two owners (INT-193). And
`check_intents` being fixed for a defect while `check_dotmeta`, immediately beside it in the same
file, was not.

### 3. Derive, don't duplicate

> If something can be generated from an existing fact, don't maintain another copy.

**Earned from:** the health check count reading 22 in one document, 14 in another, and 34 in the
code. And `docs/public/`, which was deleted as a duplicate and regenerated by its own generator,
because deleting generated output is never the fix.

### 4. Activation is reversible

> Trying something should be cheap to undo.

**Earned from:** the correction in decision 146. NixOS provides immutable, independently bootable
generations and explicit rollback -- **not** atomic activation. Activation scripts, systemd changes
and migrations can fail halfway with side effects, and nothing returns the external world to its
prior state.

★ So the requirement is reversibility, which can be designed for, rather than transactionality,
which cannot be promised.

### 5. Recovery is independent

> The mechanism that saves the system cannot depend on the system being saved.

**Earned from:** the boot chain. Secure Boot is enforcing, and the signing keys that produce every
UKI exist in exactly one place -- `/var/lib/sbctl`, on the LUKS-encrypted root they would be needed
to recover. The rescue USB is rejected under enforcement and silently falls through.

⚠️ A rollback command is useless if the system prevents you reaching the environment that runs it.

### 6. The user is the authority

> There is no hypothetical downstream user whose preferences need to be preserved.

**Earned from:** the ruling of 2026-08-17 -- Zero Core is for one person. That is what keeps
*a profile with one consumer is ceremony, not structure* intact, and it is why generated
user-facing documentation has no audience.

### 7. The implementation is replaceable

> A first-party tool earns its place by capability, not authorship.

**Earned from:** more than thirty tools already retired, and the bar, notification and launcher
comparisons opened without sentiment. Writing it does not entitle it to stay.

### 8. The interface is opinionated; the substrate is not

> The desktop can be highly decided without making the underlying system fragile.

**Earned from:** decision 145, and the reason for leaving Omarchy. Its customization boundary is
partly file-based, so some refresh paths treat generated configuration as replaceable and a user
edit becomes collateral. **Profiles carry the opinion; options preserve ownership.** Never make the
user's customization surface the same artifact as the project's update surface.

## The exception, stated rather than hidden

⚠️ **`fsh` is kept for reasons outside law 7.** Ruled explicitly: *"the one project I know I am
keeping -- I put a lot of work in and it keeps me inspired of doing more."* That is not a
capability argument.

★ **And it is legitimate, because law 6 outranks law 7.** The user is the authority, so a tool may
be kept because he wants it kept.

This is recorded rather than quietly tolerated. **A law broken silently the first time it is applied
stops being a law**; a law with a stated exception, justified by another law, holds. That the eight
can express their own exception without contradiction is the evidence they are a set rather than a
list.

## Precedence

Where two laws pull in different directions, **law 6 is the tiebreak.** It is the only one that
describes who decides, and the others describe how.

## Consequences

- A proposed rule that cannot name the failure it prevents is a preference, and does not join this
  list.
- AGENTS.md's Design Philosophy points here rather than restating, per law 3.
- Tool comparisons get a criterion: capability, not authorship -- with the user free to override it
  and say so.
