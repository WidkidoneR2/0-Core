# .githooks

Tracked git hooks. Point git at them once per clone:

    git config core.hooksPath .githooks

## Why tracked, and why one command

`.git/hooks/` is NOT versioned, so a fresh clone has no hooks at all until someone remembers to
install them -- and nobody remembers. A tracked directory plus `core.hooksPath` makes the hooks
part of the repository, reviewed like any other file.

⚠️ THE ONE COMMAND IS THE COST, and it is deliberate. Git will not let a repository silently point
its own hooks at tracked, executable content -- that would let a clone run code before you read it.
Requiring the operator to opt in is the security property, not an oversight.

## What runs

Everything is `zero-gate`, which is in this repository and has no dependencies. It is silent on
success and reports anything it could not run rather than passing quietly.

    pre-commit   secrets, risk tiers, formatting
    pre-push     the shell test suite

## What this replaced

A `.pre-commit-config.yaml` GENERATED by `git-hooks.nix`, whose every entry was an absolute
`/nix/store` path. Off NixOS those do not resolve, and the framework SKIPS hooks it cannot find --
so all four gates would have vanished silently on a new distribution, with no message.
