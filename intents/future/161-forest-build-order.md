## The Revised Build Order

Two tracks running in parallel:

### Track A — Core Intelligence (sequential, foundational)
```
v12 Strategy    (INT-151) — the forest plans
v13 Autonomy    (INT-156) — the forest acts
v14 Partnership (INT-158) — the forest collaborates
```

### Track B — Partner Tools (can build alongside Track A)
```
faelight-docs v2  (INT-157) — accurate self-documentation
faelight-context  (INT-159) — deep codebase understanding
faelight-memory   (INT-160) — persistent knowledge layer
faelight-shell    (INT-146) — daily driver (ongoing)
```

## Why This Order

Track A must be sequential — each version builds on the last.
v12 needs v11 (prediction). v13 needs v12 (strategy).
v14 needs v13 (trust). Cannot skip steps.

Track B can run in parallel because:
- faelight-docs v2 is independent of core version
- faelight-context uses existing evolution domain
- faelight-memory uses existing predict + state.db
- faelight-shell is always ongoing

## The Convergence Point

When v13 ships and Jarvis score reaches 95/100,
Track A and Track B converge:

faelight-context + faelight-memory + Core v13
= the foundation for genuine partnership

The projects not yet revealed will be built here.

## Burn Both Ends Strategy

Session structure going forward:
- Core version work: 40% of sessions
- Shell daily driver: 40% of sessions  
- Partner tools: 20% of sessions

The shell must become the daily driver before v13 ships.
A partner that lives in a shell you do not use daily
is a partner you will never trust.
