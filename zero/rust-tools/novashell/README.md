# 🌲 NovaShell

**Version:** 3.9.0 &nbsp;|&nbsp; **License:** MIT &nbsp;|&nbsp; **Status:** active &nbsp;|&nbsp; **Binary:** `nsh`

## 📖 Description

The forest's own shell -- speaks human first, UNIX as fallback. Structured data,
natural-language verbs, parallel execution.

The crate is `novashell`; the binary it produces is `nsh`.

## What it is, and what it is not

nsh is the shell you TYPE. It is not the login shell -- bash holds that seat in
`/etc/passwd` and starts nsh from `.bashrc`, deliberately. A shell that cannot be
your login shell can be broken on a Tuesday without locking you out of your own
machine.

It is not POSIX and does not try to be. Where a construct is not modelled, the
line goes to `sh` rather than being guessed at.

Some of what it does that a POSIX shell does not:

- structured tables through pipes -- `ps | where cpu > 1 | sort cpu desc | first 5`
- `|||` for genuine parallel execution
- `?` prefix to ask in plain words
- a safety guard that challenges destructive commands, on both doors and on every
  executing segment of a chain
- session save, load and replay

## Build

```sh
cargo build --release -p novashell
```

## Deploy

```sh
ship nsh
```

`ship` installs to `~/.local/bin`, keeps a versioned backup, and records the
deploy. `ship --retire nsh` is the inverse.

## Test

```sh
nsh-test
```

Drives the real REPL through a pty as well as the `-c` door, because the two
behave differently and testing only one is how a whole class of bugs stayed
hidden.
